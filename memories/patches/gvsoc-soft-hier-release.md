# GVSoC soft_hier_release patches

## Summary
The project runs SoftHier on GVSoC branch `soft_hier_release` at upstream commit [`d806a84`](https://github.com/gvsoc/gvsoc/tree/d806a84c5785237547f504c2e34a4d9f230cb437) plus a series of ten patches. The canonical patch files, their apply order and the commit messages that give each rationale are in the code repository under `infra/softhier/gvsoc-patches/` ([series README](https://github.com/HaozeG/SoftHier-VLA/blob/e832bfb749c38388f9ee930e1d25c03b9917b971/infra/softhier/gvsoc-patches/README.md)); the findings F1 to F19 and their evidence are in the design document's findings table ([design](https://github.com/HaozeG/SoftHier-VLA/blob/e832bfb749c38388f9ee930e1d25c03b9917b971/docs/designs/smolvla-softhier-baseline.md), section "Simulator findings"). This table adds only what those files do not hold in one place: upstream status, measured impact and links, keyed by finding ID. It was read from code-repository commit `e832bfb`; patch numbers are as of that commit and change when the series is re-exported. The stage of work these fixes enabled is the status entry [Basic integration of components](../status/basic-integration-of-components.md).

- Upstream status: no upstream pull request is recorded in either file. The design names F13, F14, F15 (with F3), F16 and F17 as upstream candidates and F5 as a feature the stock tree lacks; F1 and F8 follow the owner's notes and have no effect on this workload.
- Not patched, so not in the table: F2, F4, F6, F7, F9 to F11 (no symptom), F12 (host-speed models, patch not available), F19 (open, not investigated).
