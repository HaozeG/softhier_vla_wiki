# SoftHier kernel repository (implementation/) patches

## Summary
The hand-written SoftHier kernels (FlatAttention, SUMMA GEMM, RMSNorm, Activation) live in `implementation/` of the GVSoC fork, branch `softhier_deeploy` at [`52859c3`](https://github.com/HaozeG/gvsoc/tree/52859c3109fe9ecbdc3ca73706a4701bb3293477/implementation). The project's changes are commits on branch `gelu-layernorm-kernels` of the same repository; the commit messages are the canonical record (rationale, numbers, how each was checked). This table adds only upstream status, measured impact and links, keyed by finding ID. Finding IDs F20 onward are numbered in this note and continue the baseline design's F1 to F19 ([GVSoC soft_hier_release patches](gvsoc-soft-hier-release.md)).

- The same branch adds kernels for SmolVLA: GELU (tanh form) and LayerNorm for the vision encoder, and Eltwise (add, bias, scale, axpy, RoPE, pixel shuffle) for the remaining elementwise and data operators. They are features, not fixes, so they are not rows. Their numbers are in the commit messages of `e0dd966`, `e758b0b` and `dc749bc`.
- All measurements: simulated on GVSoC with DRAMSys HBM, arch `implementation/config/arch/arch.py` (16 clusters, Spatz on 4 cores each), output compared on the device with a golden that replays the kernel's fp16 instruction sequence.
- Simulator defects F25 and F26 are worked around in kernel code, not fixed in the simulator.
- The kernels' per-call times at SmolVLA shapes make up the composed baseline in [Analyzing the needs of one model: SmolVLA](../status/analyzing-the-needs-of-one-model-smolvla.md).
- Not patched, so not in the table: F27, the GVSoC ISS has no timing model for `vfwadd.wv`, `vfwsub.vf`, `vmv.x.s`, `vmv.s.x` and `vmv.v.i` (zero cycles), so LayerNorm timings are optimistic; recorded in the header of `sw/LayerNorm/include/LayerNorm.h` ([e758b0b](https://github.com/HaozeG/gvsoc/commit/e758b0b281bf1bdb5e9edcce7a75eed78530c556)).
- Not patched, so not in the table: F30, FlatAttention computes less than asked for some shapes. Async mode runs `heads_per_group / 2` head pairs (floor), so an odd count per group drops a head and one head per group computes nothing; heads per group is `heads / groups` (floor) and the block counts are `Sq / Br` and `Skv / Bc` (floor), so heads and rows beyond a multiple are dropped. Read from the code, not run (inference). The output is never checked, so nothing reports it. The project's runs pad sequence lengths up and use only head splits the kernel can do ([FlatAttention.h:434,539](https://github.com/HaozeG/gvsoc/blob/52859c3109fe9ecbdc3ca73706a4701bb3293477/implementation/sw/FlatAttention/include/FlatAttention.h#L434)).
- Not patched, so not in the table: F31, SummaGEMM rounds its tile counts up and always moves full tiles, so a shape that is not a multiple of 4 x tile reads and writes past the arrays; the project's runs pad M, N and K up ([SummaGEMM.h:142-144](https://github.com/HaozeG/gvsoc/blob/52859c3109fe9ecbdc3ca73706a4701bb3293477/implementation/sw/SummaGEMM/include/SummaGEMM.h#L142)).
