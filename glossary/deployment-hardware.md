# Deployment hardware

## Summary
Words for the chips a policy runs on and how well it uses them: tile, PE, SRAM, many-PE chip, MLIR, TPU, MFU; and for profiling a workload on them: GEMM, kernel, batch size, arithmetic intensity, roofline, ridge point, memory- and compute-bound, DVFS, EMC, SLO. All terms are standard (scope field); the SoftHier chip terms come from the project README. This branch is outside the robot-side map of the field ([physical AI map](../knowledge/physical-ai-map.md)).

## Terms
| Term                                         | Meaning                                                                                                                                                                                         | Scope | Defined in                                                                 |
| -------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----- | -------------------------------------------------------------------------- |
| tile                                         | One tile of a tile-based many-PE chip: a group of processing elements with their local memory, repeated across the chip.                                                                        | field | [SoftHier and the project](../knowledge/softhier-and-the-project.md)       |
| PE (processing element)                      | One small compute unit of a many-PE chip.                                                                                                                                                       | field | [SoftHier and the project](../knowledge/softhier-and-the-project.md)       |
| SRAM                                         | Static random-access memory: fast memory on the chip itself.                                                                                                                                    | field | [SoftHier and the project](../knowledge/softhier-and-the-project.md)       |
| many-PE chip, tile-based chip                | A chip built from many processing elements grouped in tiles.                                                                                                                                    | field | [SoftHier and the project](../knowledge/softhier-and-the-project.md)       |
| MLIR                                         | A compiler framework for building toolchains that translate a model into code for a chip. Standard gloss; the project README names it.                                                          | field | [SoftHier and the project](../knowledge/softhier-and-the-project.md)       |
| TPU                                          | Tensor processing unit: Google's accelerator chip for models; the cloud service of an early VLA ran on several of them.                                                                         | field | [RT-2](../resources/models/rt-2.md)                                        |
| MFU (model FLOPs utilization)                | The share of a chip's peak arithmetic rate that a model's work actually uses. Standard gloss; the project README names it as an aim.                                                            | field | [SoftHier and the project](../knowledge/softhier-and-the-project.md)       |
| GEMM                                         | General matrix multiply: the matrix-times-matrix operation that most of a transformer's work reduces to. Standard gloss.                                                                        | field | [benchmark workloads](../knowledge/vla-benchmark-workloads.md)             |
| kernel (GPU kernel)                          | One function launched on the GPU, such as one GEMM; profilers report time per kernel. Launching many small kernels adds host-side overhead. Standard gloss.                                     | field | [benchmark workloads](../knowledge/vla-benchmark-workloads.md)             |
| batch size                                   | How many independent inputs one model call processes together. A single robot sending one request at a time gives a batch of a single input. Standard gloss.                                    | field | [benchmark workloads](../knowledge/vla-benchmark-workloads.md)             |
| arithmetic intensity (AI)                    | The arithmetic a kernel does per byte it moves to or from memory, in FLOP per byte. Low intensity means the kernel waits on memory. Standard gloss.                                             | field | [benchmark workloads](../knowledge/vla-benchmark-workloads.md)             |
| roofline model                               | A performance model that bounds a kernel's speed by the lower of the peak arithmetic rate and memory bandwidth times arithmetic intensity. Standard gloss.                                      | field | [benchmark workloads](../knowledge/vla-benchmark-workloads.md)             |
| ridge point                                  | The arithmetic intensity at which a chip's two roofline limits meet: its peak arithmetic rate divided by its peak memory bandwidth. Standard gloss.                                             | field | [benchmark workloads](../knowledge/vla-benchmark-workloads.md)             |
| memory-bound, compute-bound                  | A kernel is memory-bound when its arithmetic intensity is below the ridge point, so memory bandwidth limits it, and compute-bound when above, so the arithmetic rate limits it. Standard gloss. | field | [benchmark workloads](../knowledge/vla-benchmark-workloads.md)             |
| DVFS (dynamic voltage and frequency scaling) | Lowering or raising a chip's clock frequency (and voltage) at run time to trade speed for power. Standard gloss.                                                                                | field | [benchmark workloads](../knowledge/vla-benchmark-workloads.md)             |
| EMC (external memory controller)             | The memory-controller clock domain on NVIDIA Jetson chips; its frequency sets DRAM bandwidth. Standard gloss.                                                                                   | field | [Jung et al.](../resources/serving/vla-workload-characterization-kaist.md) |
| SLO (service-level objective)                | A target a deployment must meet, such as a maximum latency, power, energy or control cycle. Standard gloss.                                                                                     | field | [benchmark workloads](../knowledge/vla-benchmark-workloads.md)             |
