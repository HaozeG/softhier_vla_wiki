# Deployment hardware

## Summary
Words for the chips a policy runs on and how well it uses them: tile, PE, SRAM, many-PE chip, MLIR, TPU, MFU; and for profiling a workload on them: GEMM, kernel, batch size, arithmetic intensity, roofline, ridge point, memory- and compute-bound, DVFS, EMC, SLO; and for speeding it up: CUDA graph, kernel fusion, FP8 and NVFP4. and the named parts of the SoftHier model and its software: GVSoC, Snitch, RedMulE, Spatz, iDMA, TCDM, SUMMA, FlatAttention. All terms are standard (scope field); the SoftHier chip terms come from the project README, the named SoftHier parts from softhier-mlir's README and design document, the SoftHier model's GVSoC branch and the project's first baseline design. This branch is outside the robot-side map of the field ([physical AI map](../knowledge/physical-ai-map.md)).

## Terms
| Term                                         | Meaning                                                                                                                                                                                                                                                                                                                                | Scope | Defined in                                                                 |
| -------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----- | -------------------------------------------------------------------------- |
| tile                                         | One tile of a tile-based many-PE chip: a group of processing elements with their local memory, repeated across the chip.                                                                                                                                                                                                               | field | [SoftHier and the project](../knowledge/softhier-and-the-project.md)       |
| PE (processing element)                      | One small compute unit of a many-PE chip.                                                                                                                                                                                                                                                                                              | field | [SoftHier and the project](../knowledge/softhier-and-the-project.md)       |
| SRAM                                         | Static random-access memory: fast memory on the chip itself.                                                                                                                                                                                                                                                                           | field | [SoftHier and the project](../knowledge/softhier-and-the-project.md)       |
| many-PE chip, tile-based chip                | A chip built from many processing elements grouped in tiles.                                                                                                                                                                                                                                                                           | field | [SoftHier and the project](../knowledge/softhier-and-the-project.md)       |
| MLIR                                         | A compiler framework for building toolchains that translate a model into code for a chip. Standard gloss; the project README names it.                                                                                                                                                                                                 | field | [SoftHier and the project](../knowledge/softhier-and-the-project.md)       |
| TPU                                          | Tensor processing unit: Google's accelerator chip for models; the cloud service of an early VLA ran on several of them.                                                                                                                                                                                                                | field | [RT-2](../resources/models/rt-2.md)                                        |
| MFU (model FLOPs utilization)                | The share of a chip's peak arithmetic rate that a model's work actually uses. Standard gloss; the project README names it as an aim.                                                                                                                                                                                                   | field | [SoftHier and the project](../knowledge/softhier-and-the-project.md)       |
| GEMM                                         | General matrix multiply: the matrix-times-matrix operation that most of a transformer's work reduces to. Standard gloss.                                                                                                                                                                                                               | field | [benchmark workloads](../knowledge/vla-benchmark-workloads.md)             |
| kernel (GPU kernel)                          | One function launched on the GPU, such as one GEMM; profilers report time per kernel. Launching many small kernels adds host-side overhead. Standard gloss.                                                                                                                                                                            | field | [benchmark workloads](../knowledge/vla-benchmark-workloads.md)             |
| batch size                                   | How many independent inputs one model call processes together. A single robot sending one request at a time gives a batch of a single input. Standard gloss.                                                                                                                                                                           | field | [benchmark workloads](../knowledge/vla-benchmark-workloads.md)             |
| arithmetic intensity (AI)                    | The arithmetic a kernel does per byte it moves to or from memory, in FLOP per byte. Low intensity means the kernel waits on memory. Standard gloss.                                                                                                                                                                                    | field | [benchmark workloads](../knowledge/vla-benchmark-workloads.md)             |
| roofline model                               | A performance model that bounds a kernel's speed by the lower of the peak arithmetic rate and memory bandwidth times arithmetic intensity. Standard gloss.                                                                                                                                                                             | field | [benchmark workloads](../knowledge/vla-benchmark-workloads.md)             |
| ridge point                                  | The arithmetic intensity at which a chip's two roofline limits meet: its peak arithmetic rate divided by its peak memory bandwidth. Standard gloss.                                                                                                                                                                                    | field | [benchmark workloads](../knowledge/vla-benchmark-workloads.md)             |
| memory-bound, compute-bound                  | A kernel is memory-bound when its arithmetic intensity is below the ridge point, so memory bandwidth limits it, and compute-bound when above, so the arithmetic rate limits it. Standard gloss.                                                                                                                                        | field | [benchmark workloads](../knowledge/vla-benchmark-workloads.md)             |
| DVFS (dynamic voltage and frequency scaling) | Lowering or raising a chip's clock frequency (and voltage) at run time to trade speed for power. Standard gloss.                                                                                                                                                                                                                       | field | [benchmark workloads](../knowledge/vla-benchmark-workloads.md)             |
| EMC (external memory controller)             | The memory-controller clock domain on NVIDIA Jetson chips; its frequency sets DRAM bandwidth. Standard gloss.                                                                                                                                                                                                                          | field | [Jung et al.](../resources/serving/vla-workload-characterization-kaist.md) |
| SLO (service-level objective)                | A target a deployment must meet, such as a maximum latency, power, energy or control cycle. Standard gloss.                                                                                                                                                                                                                            | field | [benchmark workloads](../knowledge/vla-benchmark-workloads.md)             |
| CUDA graph                                   | A recorded sequence of GPU kernels that is replayed as one launch, removing the per-kernel launch cost of eager execution. Standard gloss.                                                                                                                                                                                             | field | [benchmark workloads](../knowledge/vla-benchmark-workloads.md)             |
| kernel fusion                                | Merging several GPU operations into one kernel so intermediate results stay on chip instead of going back to memory. Standard gloss.                                                                                                                                                                                                   | field | [benchmark workloads](../knowledge/vla-benchmark-workloads.md)             |
| FP8, NVFP4                                   | Low-precision floating-point formats for weights and arithmetic: FP8 stores each value in one byte; NVFP4 is NVIDIA's half-byte format that shares a scale across each small block of values. Standard gloss.                                                                                                                          | field | [benchmark workloads](../knowledge/vla-benchmark-workloads.md)             |
| NPU (neural processing unit)                 | An accelerator chip designed for neural-network inference, such as Huawei's Ascend line. Standard gloss.                                                                                                                                                                                                                               | field | [benchmark workloads](../knowledge/vla-benchmark-workloads.md)             |
| XPU                                          | Umbrella term for any processor type (CPU, GPU, NPU and others); Intel also uses it for its GPUs and their PyTorch backend. Standard gloss.                                                                                                                                                                                            | field | [benchmark workloads](../knowledge/vla-benchmark-workloads.md)             |
| SoC (system on chip)                         | One chip that combines CPU, GPU or other accelerators and a memory controller, often with memory shared between them, such as NVIDIA Jetson. Standard gloss.                                                                                                                                                                           | field | [benchmark workloads](../knowledge/vla-benchmark-workloads.md)             |
| static-graph compilation                     | Compiling a whole model ahead of time into a fixed computation graph for the target chip, instead of dispatching operations one by one at run time (eager execution). Standard gloss.                                                                                                                                                  | field | [benchmark workloads](../knowledge/vla-benchmark-workloads.md)             |
| GVSoC                                        | An event-based simulator of systems on chip, in which each hardware component is a Python description paired with a C++ simulation engine. The SoftHier model runs in it, on branch `soft_hier_release` of the GVSoC repository.                                                                                                       | field | [SoftHier and the project](../knowledge/softhier-and-the-project.md)       |
| Snitch                                       | The small RISC-V cores of a SoftHier cluster, from the PULP platform. In softhier-mlir one core issues the DMA transfers and another starts the matrix and vector engines.                                                                                                                                                             | field | [GVSoC patch log](../memories/patches/gvsoc-soft-hier-release.md)          |
| RedMulE                                      | The matrix-multiply engine of each SoftHier cluster: a systolic array that computes a matrix product into an output tile it accumulates in place (Y = X·W + Y), in fp16 and other formats. softhier-mlir spells it RedMule.                                                                                                            | field | [GVSoC patch log](../memories/patches/gvsoc-soft-hier-release.md)          |
| Spatz                                        | The vector unit of a SoftHier cluster, used for softmax-class math such as exponentials and max and sum reductions; the vector engine of the SoftHier architecture figure.                                                                                                                                                             | field | [SoftHier and the project](../knowledge/softhier-and-the-project.md)       |
| iDMA                                         | The DMA engine of each SoftHier cluster: it moves data between HBM and the cluster's local memory without the cores, with strided copies, multicast along a mesh row or column, and reductions performed inside the network-on-chip.                                                                                                   | field | [GVSoC patch log](../memories/patches/gvsoc-soft-hier-release.md)          |
| TCDM                                         | A SoftHier cluster's local scratchpad memory (its L1), shared by the cluster's cores and engines. Another cluster's TCDM can be reached over the network-on-chip as remote TCDM.                                                                                                                                                       | field | [GVSoC patch log](../memories/patches/gvsoc-soft-hier-release.md)          |
| SUMMA                                        | The GEMM dataflow softhier-mlir uses across the SoftHier cluster mesh: each cluster keeps one output tile (output-stationary), clusters on the diagonal load operand panels from HBM and broadcast them along their mesh row and column, and partial sums along the shared dimension are combined by reduction in the network-on-chip. | field | [GVSoC patch log](../memories/patches/gvsoc-soft-hier-release.md)          |
| FlatAttention                                | An attention kernel for SoftHier-like tile-based chips, covering multi-head, multi-query and grouped-query attention; it is one of the SoftHier kernel tests on GVSoC, and softhier-mlir describes it with the same pattern as its GEMM (SUMMA dataflow, RedMulE, iDMA broadcast and reduction, double buffering).                     | field | [dataflow hardware paper map](../knowledge/dataflow-hw-paper-map.md)       |
