# Action generation

## Summary
How a policy's action head turns features into actions. The kinds form three families: discrete tokens, single-pass continuous heads (regression, CVAE) and iterative continuous heads that refine noise (diffusion, flow matching). Diffusion and flow matching are siblings, each with its own step vocabulary. All terms are standard (scope field); the head kinds are compared in [action representation and chunking](../knowledge/action-representation-and-chunking.md).

```text
action head
+-- discrete tokens ......... binning, FAST (a tokenizer); one pass per token
+-- single pass, continuous . parallel regression (L1 loss); CVAE decoder
+-- iterative, from noise ... diffusion: trained to predict the noise
                              (DDPM, DDIM sampler, denoising steps, score)
                              flow matching: trained to regress a velocity
                              (ODE, Euler step, flow time, flow steps)
   shared by both iterative kinds: noisy chunk; network = action expert
   or DiT (group "model parts and attention")
```

| action head                                | The part of a policy that turns the model's features into actions. Designs differ mostly here: discrete tokens, a single-pass continuous head, or an iterative head that refines noise.                                                                                                                                                         | field | [VLA architecture overview](../knowledge/vla-architecture-overview.md)                   |

| FAST                                       | A tokenizer that compresses an action chunk into fewer discrete tokens. The tokens are still decoded one at a time.                                                                                                                                                                                                                             | field | [action representation and chunking](../knowledge/action-representation-and-chunking.md) |
| parallel regression                        | One pass writes all actions of a chunk through a regression head, which outputs the numbers directly instead of tokens. It predicts one answer per input, so it averages multimodal demonstrations.                                                                                                                                             | field | [action representation and chunking](../knowledge/action-representation-and-chunking.md) |
| L1 loss                                    | A training loss that penalises the absolute difference between the predicted and the true actions; it is used to train regression heads. Standard gloss.                                                                                                                                                                                        | field | [OpenVLA-OFT](../resources/models/openvla-oft.md)                                        |
| CVAE (conditional variational autoencoder) | A generative model with a latent variable: during training an encoder compresses the true action chunk into a latent and a decoder rebuilds the chunk from the observation and the latent. At run time only the decoder runs, in one pass; ACT sets the latent to zero.                                                                         | field | [action representation and chunking](../knowledge/action-representation-and-chunking.md) |
| diffusion                                  | An iterative head: start from random noise shaped like the action chunk and remove noise step by step, with a network trained to predict the added noise (equivalently, the score). Standard DDPM sampling adds fresh noise at each step; samplers such as DDIM take fewer steps. How much noise sampling adds is a choice made after training. | field | [action representation and chunking](../knowledge/action-representation-and-chunking.md) |
| DDPM, DDIM                                 | DDPM (denoising diffusion probabilistic model): the standard discrete-time diffusion model, trained to predict the added noise. DDIM: a sampler for a trained DDPM that uses fewer inference steps than training steps.                                                                                                                         | field | [Diffusion Policy](../resources/models/diffusion-policy.md)                              |
| denoising steps                            | The number of noise-removal steps one diffusion call runs; each step calls the denoising network once.                                                                                                                                                                                                                                          | field | [Diffusion Policy](../resources/models/diffusion-policy.md)                              |
| noise prediction, score                    | The diffusion network predicts the noise in its input; this is equivalent to the score, the direction in which the data becomes more likely.                                                                                                                                                                                                    | field | [Diffusion Policy](../resources/models/diffusion-policy.md)                              |
| flow matching                              | An iterative head: start from random noise shaped like the action chunk and move it along a velocity field that a trained network gives, by integrating an ODE. Training regresses the network onto the velocity of a known path from noise to data. Sources call it either a sibling of diffusion or a generalisation of it.                   | field | [action representation and chunking](../knowledge/action-representation-and-chunking.md) |
| noisy chunk, flow time                     | The current guess for the chunk, which starts as noise, and how far along the refinement it is.                                                                                                                                                                                                                                                 | field | [SmolVLA](../knowledge/smolvla.md)                                                       |
| velocity, Euler step                       | The network outputs a velocity, the direction in which to move the noisy chunk; an Euler step moves it a small way along that direction.                                                                                                                                                                                                        | field | [SmolVLA](../knowledge/smolvla.md)                                                       |
| flow step, flow steps                      | The number of refinement steps one flow-matching call runs; each step calls the network once, so more steps mean a longer call.                                                                                                                                                                                                                 | field | [one VLA call](../knowledge/one-vla-call.md)                                             |

## Flow matching and diffusion
**Flow matching in one paragraph.** The expert is trained so that, given a noisy chunk and a flow time, it predicts the velocity that points toward the true action chunk. At run time the model starts from pure noise and applies T Euler steps; each step calls the expert once. After the last step the chunk is the predicted actions.

**Diffusion in one paragraph.** The network is trained to predict the noise that was added to a true action chunk. At run time the model starts from pure noise and applies a number of denoising steps (Diffusion Policy writes this number K), each subtracting predicted noise and, in DDPM sampling, adding a little fresh noise. DDIM runs fewer steps than training used.
