# Action generation

## Summary
The ways a VLA turns its features into actions (discrete tokens, parallel regression, flow matching) and the vocabulary of the flow loop. All terms are standard (scope field).

## Terms
| Term                             | Meaning                                                                                                                                                                                                                                          | Scope | Defined in                                                                               |
| -------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ----- | ---------------------------------------------------------------------------------------- |
| discrete action tokens (binning) | Each action dimension is cut into bins and the language model writes the bin numbers as tokens, one pass per token. It reuses the language model unchanged but needs many sequential passes.                                                     | field | [action representation and chunking](../knowledge/action-representation-and-chunking.md) |
| FAST                             | A way to compress an action chunk into fewer tokens. The tokens are still decoded one at a time.                                                                                                                                                 | field | [action representation and chunking](../knowledge/action-representation-and-chunking.md) |
| parallel regression              | One pass writes all actions of a chunk through a regression head, which outputs the numbers directly instead of tokens.                                                                                                                          | field | [action representation and chunking](../knowledge/action-representation-and-chunking.md) |
| L1 loss                          | A training loss that penalises the absolute difference between the predicted and the true actions; it is used to train regression heads. Standard gloss.                                                                                         | field | [OpenVLA-OFT](../resources/models/openvla-oft.md)                                        |
| flow matching                    | Start from random noise shaped like the action chunk and refine it in small steps; a trained network says in which direction each step should move. The refined chunk is the model's actions.                                                    | field | [SmolVLA](../knowledge/smolvla.md)                                                       |
| diffusion                        | The same refine-from-noise idea with a different step rule. A sampler such as DDIM lets it use fewer steps.                                                                                                                                      | field | [flow-step reduction](../knowledge/flow-step-reduction.md)                               |
| DDIM                             | A sampler for diffusion models that reaches an answer in fewer steps than the original sampler. Standard gloss.                                                                                                                                  | field | [flow-step reduction](../knowledge/flow-step-reduction.md)                               |
| action expert                    | The small network that runs the flow steps: it reads what the language model computed and writes the action chunk.                                                                                                                               | field | [SmolVLA](../knowledge/smolvla.md)                                                       |
| noisy chunk, flow time           | The current guess for the chunk, which starts as noise, and how far along the refinement it is.                                                                                                                                                  | field | [SmolVLA](../knowledge/smolvla.md)                                                       |
| velocity, Euler step             | The expert outputs a velocity, the direction in which to move the noisy chunk; an Euler step moves it a small way along that direction.                                                                                                          | field | [SmolVLA](../knowledge/smolvla.md)                                                       |
| flow steps (T)                   | The number of refinement steps one call runs; each step calls the expert once, so more steps mean a longer call.                                                                                                                                 | field | [flow-step reduction](../knowledge/flow-step-reduction.md)                               |
| inpainting and guidance          | Inpainting fills in the part of a sequence that is not fixed while the fixed part stays as given; guidance nudges a generation step toward a target. Real-time chunking uses both to keep a new chunk consistent with actions already committed. | field | [real-time chunking](../resources/serving/real-time-chunking.md)                         |
| streaming decoding               | Keeping several chunks at different noise levels and advancing all of them by one step per pass, so that each pass finishes one chunk.                                                                                                           | field | [flow-step reduction](../knowledge/flow-step-reduction.md)                               |
| DCT and BPE                      | DCT, the discrete cosine transform, re-expresses a signal as a sum of waves of different frequencies; BPE, byte-pair encoding, merges frequent symbol pairs into single tokens. FAST uses both to compress an action chunk into fewer tokens.    | field | [FAST](../resources/models/fast-tokenizer.md)                                            |



## Flow matching
**Flow matching in one paragraph.** The expert is trained so that, given a noisy chunk and a flow time, it predicts the velocity that points toward the true action chunk. At run time the model starts from pure noise and applies T Euler steps; each step calls the expert once. After the last step the chunk is the predicted actions.
