# Model and attention

## Summary
What a VLA is made of and the transformer words used for how its parts exchange data. All terms are standard (scope field).

## Terms
| Term                                  | Meaning                                                                                                                                                                                                                           | Scope | Defined in                                                                                 |
| ------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----- | ------------------------------------------------------------------------------------------ |
| VLA                                   | Vision-language-action model: takes camera images, a language instruction and usually robot state, and outputs actions for a robot. It is the kind of model whose speed this wiki studies.                                        | field | [VLA architecture overview](../knowledge/vla-architecture-overview.md)                     |
| VLM                                   | Vision-language model: an image encoder plus a language model that reads both images and text. A VLA is built on one and adds a way to output actions.                                                                            | field | [VLA architecture overview](../knowledge/vla-architecture-overview.md)                     |
| vision encoder                        | Turns an image into patch tokens, one for each small region of the picture. SigLIP and DINOv2 are common choices in VLAs.                                                                                                         | field | [VLA architecture overview](../knowledge/vla-architecture-overview.md)                     |
| projector                             | A small network that maps the image encoder's features into the language model's token space, so that the language model can read pictures like words.                                                                            | field | [VLA architecture overview](../knowledge/vla-architecture-overview.md)                     |
| token                                 | A vector standing for one piece of input: an image patch, a word piece or the robot state. The more tokens a model reads, the more work it does.                                                                                  | field | [VLA architecture overview](../knowledge/vla-architecture-overview.md)                     |
| parameters (B, M)                     | The learned numbers of a model, counted in billions (B) or millions (M); a rough measure of its size.                                                                                                                             | field | [VLA architecture overview](../knowledge/vla-architecture-overview.md)                     |
| LM backbone (LLM)                     | The language-model layers that process all tokens together; in a VLA they combine what the robot sees with what it is told.                                                                                                       | field | [VLA architecture overview](../knowledge/vla-architecture-overview.md)                     |
| prefix                                | All observation tokens given to the language model: images, text and state. It is processed once per call, and the action expert then reuses the result.                                                                          | field | [inference workload characterization](../knowledge/inference-workload-characterization.md) |
| prefill                               | The single pass that processes the whole prefix before any output is produced.                                                                                                                                                    | field | [inference workload characterization](../knowledge/inference-workload-characterization.md) |
| KV cache                              | The keys and values that each attention layer computes for the prefix, stored so that later work, such as every flow step, can read them instead of recomputing the prefix.                                                       | field | [SmolVLA](../knowledge/smolvla.md)                                                         |
| keys and values (attention)           | In attention each token offers a key to be matched and a value to be read; a token looks at others by matching against their keys and mixing their values. Stored keys and values are what the KV cache holds.                    | field | [SmolVLA](../knowledge/smolvla.md)                                                         |
| self-attention                        | Tokens look at each other, so that each token's representation is updated with information from the others.                                                                                                                       | field | [VLA architecture overview](../knowledge/vla-architecture-overview.md)                     |
| cross-attention                       | One set of tokens looks at another set's keys and values. The action expert uses it to read what the language model computed.                                                                                                     | field | [SmolVLA](../knowledge/smolvla.md)                                                         |
| causal and bidirectional attention    | Causal: each token sees only earlier tokens. Bidirectional: every token sees all tokens. The choice decides, for example, whether all actions of a chunk can be produced in a single pass.                                        | field | [action representation and chunking](../knowledge/action-representation-and-chunking.md)   |
| pixel shuffle                         | Rearranges neighbouring image patch tokens into fewer, wider ones, so that the language model has fewer image tokens to read.                                                                                                     | field | [SmolVLA](../knowledge/smolvla.md)                                                         |
| MLP                                   | Multi-layer perceptron: a small feed-forward network. In a transformer it is the block after attention in each layer, and VLAs also use small ones as projectors and action heads. Standard gloss; the linked note uses the term. | field | [VLA architecture overview](../knowledge/vla-architecture-overview.md)                     |
| ACT                                   | A small policy whose single forward pass gives a whole action chunk, with no step-by-step decoding. It appears in the sources as a lightweight comparison point.                                                                  | field | [action representation and chunking](../knowledge/action-representation-and-chunking.md)   |
| DiT                                   | Diffusion transformer: a transformer used as the denoising network of a diffusion or flow model. In GR00T N1 it is the action module that turns a noisy action chunk into actions.                                                | field | [VLA architecture overview](../knowledge/vla-architecture-overview.md)                     |
| action head                           | The part of a VLA that turns the model's features into actions. Designs differ mostly here: discrete tokens, parallel regression, or a flow expert.                                                                               | field | [VLA architecture overview](../knowledge/vla-architecture-overview.md)                     |
| autoregressive decoding, decode phase | Producing output one token at a time, each pass needing the tokens already produced. The decode phase is the part of a call spent doing this, as in VLAs that write their actions as tokens.                                      | field | [inference workload characterization](../knowledge/inference-workload-characterization.md) |
