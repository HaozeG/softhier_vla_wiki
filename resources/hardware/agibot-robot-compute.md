# AgiBot X2, G1 and G2: compute platforms

## Summary
AgiBot ships different compute tiers across its lines: the interaction humanoid X2 uses two RK3588 boards (6-TOPS NPUs) and adds an Orin NX on the Ultra version; the research and data-collection G1 uses a Jetson AGX Orin 64 GB; the next-generation G2 is announced with Jetson Thor as its "core domain controller". Product pages give the parts but not a software map, and one source's role assignment for the X2's processors conflicts with another's. The open-source X1 humanoid is documented in more detail: an x86 main controller runs the reinforcement-learning walking policy at a 1 kHz control setting and drives the joints over EtherCAT. The GO-1 manipulation model is documented as a roughly 7 GB-GPU model that can run on a separate policy server.

## Details
- **X2 (vendor page):** "X2: dual RK3588; X2 Ultra: dual RK3588 plus Orin NX (157 TOPS) high-performance board". 25 DoF (Ultra 30), 1.31 m, 35 kg (Ultra 39 kg), about 500 Wh, about 2 h walking at 0.5 m/s. Standard sensors: interactive RGB camera and head touch; Ultra adds RGB-D, multi-line LiDAR for SLAM and extra cameras. The extraction of the page states that the Orin NX handles AI and interaction while the RK3588 manages motion control; a market research summary (secondary) instead lists the two RK3588 as the "brain" with the Orin NX as the flagship brain. Treat the role split as unconfirmed.
- **G1 (vendor page):** Jetson AGX Orin 64 GB (TOPS not on the page); 26 DoF (20 excluding end effectors); 3 RGB-D and 5 fisheye cameras, six-axis force sensors on both arms, chassis RGB-D and LiDAR; runtime 4 h+. The page frames the robot for "data collection and model inference" with end-cloud collaborative data collection.
- **G2 (vendor announcement):** Jetson Thor as "core domain controller", the first mass-produced robot to use it; claims 7.5× AI compute and 3.1× CPU performance over the previous generation and a 10–15% battery-life improvement (no test conditions). The stated uses of Thor: on-device model execution with less cloud reliance, reasoning for task generalization, and real-time inference for motion control. No separate motion or servo processor is described.
- **A2 Ultra:** a retailer's buyer guide lists a Jetson AGX Orin 64 GB (the page was not fetched, so this is unverified).
- **X1 open-source stack (`agibot_x1_infer`, first-party; note the X1 is a different robot from the X2):** built on AgiBot's AimRT middleware with ROS 2 Humble and ONNX Runtime for model inference; the README recommends a Linux real-time kernel patch for real-robot debugging, and the driver document requires PREEMPT_RT. Its development guide names three modules loaded into one process by `x1_cfg.yaml`: a joystick module, an RL control module (the walking policy, an ONNX file with observation history and a `decimation` setting, which the guide describes as the "sampling interval") and a DCU driver module.
- **X1 hardware path and rates (development guide):** the "X86 main controller" connects to upper-limb and lower-limb domain control units (DCUs) over EtherCAT; each DCU has three CAN-FD buses with up to 8 actuators each and an external IMU, and the bus refreshes at up to 1 kHz. The RL control module's `freq` is listed as 1000 (Hz) and joint states, IMU data and joint commands are all given as 1000 Hz topics. The guide does not say whether the ONNX policy uses a GPU, and the numeric `decimation` was not read, so the policy's own rate is not established.
- **GO-1 manipulation model (open repository and paper):** the technical report states action chunks of H = 30 and that data is recorded at a 30 Hz control frequency, and the repository sets chunk size and control frequency to 30 for pre-training (10 for its LIBERO fine-tune). These are data and chunk-playback settings, not an inference rate: a 30-step chunk played at 30 Hz lasts one second, so about one model call per second is needed. The repository lists inference at about 7 GB of GPU memory with an RTX 4090 as the example GPU, and provides a policy server with the reason "real robot may not have powerful GPUs", so observations are sent to a server and actions come back. Genie Studio is listed as the route for AgiBot G1 with GO-1 out of the box; where it runs there is not stated. The report does not state deployment hardware or inference latency; a GO-1 Air checkpoint without the latent planner is offered as the lightweight variant.
- **Not found in these sources:** the on-robot compute that runs GO-1 on the G1 or G2, GO-1 latency, the X2's per-processor roles, and the X1 policy's numeric rate.
