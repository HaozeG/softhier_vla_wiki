# Real-Time Execution of Action Chunking Flow Policies (RTC)

Black, Galliker, Levine (Physical Intelligence, UC Berkeley), arXiv 2506.07339 (v2, Dec 2025; NeurIPS 2025).

## Summary
RTC is an inference-time algorithm for asynchronous execution of diffusion/flow chunked policies. While the current chunk executes, the next chunk is generated by inpainting: actions guaranteed to execute during the inference delay are frozen, and the rest are guided (soft-masked, exponentially decaying weights) to remain consistent with the previous chunk. It needs no retraining and is tested with π0.5 on a bimanual robot.

## Key claims
- **Formulation (§3):** with inference delay d and execution horizon s (d ≤ s ≤ H − d), the first d actions of the new chunk get guidance weight 1, the last s get 0, and the middle decay exponentially. Guidance is a ΠGDM vector-Jacobian product added to the flow velocity, with weight clipping β = 5 for stability with few denoising steps.
- **Setup (§4.2, App. A.5):** π0.5, H = 50, Δt = 20 ms, n = 5 denoising steps; model latency 76 ms for baselines vs 97 ms for RTC (guidance overhead); remote inference over LAN adds 10–20 ms, giving d ≈ 6; extra +100 ms / +200 ms injected latency (d ≈ 11 / 16). Real-world inference on a single RTX 4090.
- **Simulation (Kinetix, 12 dynamic tasks, Fig. 5):** RTC beats naive async, temporal ensembling (TE) and bidirectional decoding (BID); BID uses much more compute and has 2.3× RTC's latency on π0.5 at batch 16.
- **Real world (6 tasks, 480 episodes, Fig. 6):** RTC has the best average throughput at all delays, with no degradation under injected delay; synchronous degrades roughly linearly; both TE variants triggered the robot's protective stop at +100/+200 ms.
- **Limitations (§6):** significant compute overhead over sampling directly from the base policy; only diffusion/flow policies.

## Relevance to SoftHier-VLA
RTC is the reference algorithm for hiding latency when a chunk takes longer than the control period, which is the regime an edge accelerator will be in. Its extra backpropagation through the action expert adds compute (76 → 97 ms in the paper's setup), which an accelerator must support.
