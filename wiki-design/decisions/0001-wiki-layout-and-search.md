# 0001: Wiki layout and local search

## Context
The wiki is written and read mostly by LLM agents. It needs cheap orientation (don't load
everything) and fast local retrieval without running a service or needing API keys.

## Decision
- Borrow OpenViking's concepts: a filesystem namespace (`wiki://` URIs), and per-directory
  tiered summaries — L0 `.abstract.md` (≤256 chars), L1 `.overview.md` (≤4000 chars), L2 the notes.
- Search with zvec (in-process vector DB) doing hybrid retrieval: dense vectors from
  fastembed `BAAI/bge-small-en-v1.5` (384-d, ONNX, CPU) fused with zvec full-text search via RRF.
- Sidecars are written by the maintaining agent, not generated by an API call; `wiki.py check`
  detects staleness through a `covers` hash of each directory's direct children.

## Why
- No server, no keys, one `pip install`; index is a rebuildable cache in `.index/`.
- Agents read L0/L1 first and open L2 on demand, keeping context small.
- Skipped from OpenViking: server, sessions/memory extraction, automatic LLM summarization.
